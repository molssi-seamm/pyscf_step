pyscf_step.basis module#

Basis sets and ECPs from the Basis Set Exchange, in PySCF’s internal format.

This runs in the SEAMM environment (which has basis_set_exchange) and needs no PySCF: the task’s input then carries the basis and the ECP, with its spin-orbit part, so the PySCF side reads no library. The spin-orbit terms are rebuilt and checked by pyscf_step.engine.ecp_so.

pyscf_step.basis.basis_and_ecp(symbols, basis, other_basis, uncontract=True, spin_orbit=True)[source]#

The basis and ECPs for a set of elements, as the driver takes them.

Each element uses basis if the BSE has it there, else other_basis. An element with an ECP gets the ECP’s spin-orbit part, checked against the published data; an element with an ECP but no such data is refused when spin_orbit is true.

Returns (basis {symbol: shells}, ecp {symbol: ecp}, info {symbol: {…}}).

pyscf_step.basis.scalar_ecp(name, symbol)[source]#

The element’s ECP as PySCF’s [nelec, [[l, by_r], …]], or None.

The local part (stored by the BSE with the highest angular momentum, one above the others) becomes PySCF’s l = -1. Only scalar potentials are accepted: the spin-orbit part is rebuilt separately and checked.

pyscf_step.installer module#

Installer for the PySCF plug-in.

PySCF runs in its own conda environment, seamm-pyscf by default, which this installer creates and registers in pyscf.ini. The environment holds Python 3.12 from conda-forge and PySCF from PyPI (wheels for Linux x86_64 and macOS arm64), for the CPU. GPU4PySCF, for scalar HF/DFT on NVIDIA GPUs, is added only when gpu = yes is set in pyscf.ini (or --gpu is given); the relativistic calculations always run on the CPU.

pyscf_step.installer.GPU_PACKAGES = ('gpu4pyscf-cuda12x>=1.9.1', 'cupy-cuda12x[ctk]', 'cutensor-cu12')#

The optional GPU packages (CUDA 12 build, as the Interaction EDA step uses).

class pyscf_step.installer.Installer(logger=<Logger pyscf_step.installer (WARNING)>)[source]#

Bases: InstallerBase

Handle the installation of PySCF for the PySCF step.

  1. install creates the conda environment seamm-pyscf (Python 3.12), installs PySCF in it (and GPU4PySCF if asked), checks it and writes pyscf.ini.

  2. update upgrades PySCF (within the validated series) in that environment.

  3. check and show say what is installed and whether it works.

An environment named in pyscf.ini that SEAMM did not create, or an installation = local Python, is never changed.

pyscf_step.substep module#

class pyscf_step.substep.Substep(flowchart=None, title='no title', extension=None, logger=<Logger pyscf_step.substep (WARNING)>, module=None)[source]#

Bases: Node

A base class for substeps in the PySCF subflowchart.

The top-level Pyscf step iterates over the substeps of its subflowchart and calls each substep’s run() method. Each substep is responsible for preparing its own input, invoking PySCF, analyzing its output, and storing its results.

This base class provides:

  • is_runable - whether the top-level loop should call run() on this substep. Override to return False for substeps that only contribute input (e.g., an Initialization step) rather than invoking the code.

  • input_only - a flag for “write input but don’t run” mode, useful for debugging and testing.

  • options / global_options - delegated to the parent step so that command-line options reach substeps uniformly.

  • header - a printable header for this section of step.out.

  • version / git_revision - delegated to the plug-in package so that every substep reports the plug-in’s version, not seamm.Node’s.

property git_revision#

The git revision of the pyscf_step package.

property global_options#

The global SEAMM options, delegated to the parent step.

A printable header for this section of output.

Whether to write the input only, not run PySCF.

Whether this substep should be run by the top-level loop.

Override to return False for substeps that only contribute input (e.g., an Initialization step) rather than invoking PySCF themselves.
